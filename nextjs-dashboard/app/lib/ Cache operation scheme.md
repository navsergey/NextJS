# Схема работы кэша Next.js (App Router)

Ниже представлено детальное описание и схема технического процесса взаимодействия клиента и сервера при вызове **Server Action** в связке с `revalidatePath` и `redirect`.

## 1. Архитектурная схема (Server Action + `revalidatePath` + `redirect`)

```text
 [ КЛИЕНТ / БРАУЗЕР ]                                                 [ СЕРВЕР (NEXT.JS) ]
          │                                                                     │
          │ 1. POST-запрос формы (Вызов Server Action)                          │
          ├────────────────────────────────────────────────────────────────────>│
          │                                                                     │ 2. Запись в БД (sql`INSERT...`)
          │                                                                     │ 3. Вызов revalidatePath()
          │                                                                     │    • Удаляет файлы из Data Cache
          │                                                                     │    • Удаляет Full Route Cache пути
          │                                                                     │ 4. Вызов redirect('/dashboard/invoices')
          │                                                                     │ 5. Полный рендеринг целевой страницы
          │                                                                     │    • Делает свежий SELECT из БД
          │                                                                     │    • Генерирует новый RSC Payload
          │                                                                     │
          │ 6. HTTP ОТВЕТ: Статус [ 303 See Other ]                             │
          │    • Заголовок x-action-redirect: /dashboard/invoices;push          │
          │    • Заголовок x-action-revalidated: [[],1,0]                       │
          │    • Тело ответа: Текстовый RSC Payload ("2e1:['\$', 'tr',...]")    │
          │<────────────────────────────────────────────────────────────────────┤
          │                                                                     │
 7. Чтение заголовков роутером Next.js:                                         │
    • x-action-redirect  ──> Меняет URL в браузере через history.pushState()    │
    • x-action-revalidated ──> Находит нужную ветку в LayoutRouterContext       │
                               и ставит маркер 'refetch' в parentTree           │
          │                                                                     │
 8. Магия React (Reconciliation):                                               │
    • Роутер видит маркер 'refetch', игнорирует старый кэш в parentCacheNode    │
    • Извлекает RSC Payload прямо из тела пришедшего 303-го ответа              │
    • React сравнивает новое виртуальное дерево со старым (Diffing)             │
          │                                                                     │
 9. Точечное обновление Реального DOM:                                          │
    • Вставляет только новую строку <tr> с инвойсом                             │
    • Сохраняет фокус ввода и состояние соседних элементов                      │
          ▼                                                                     ▼
```

---

## 2. Разбор механики по шагам схемы

* **Единый такт (Шаги 2–5):** На сервере все операции происходят последовательно за один запрос. Сервер не просто готовит редирект, а сразу собирает весь интерфейс (`<tr>`, `<form>` и т.до.) для страницы, на которую отправляет пользователя.
* **Передача команд (Шаг 6):** Статус `303` идет в связке с кастомными заголовками Next.js. Сервер упаковывает инструкции для кэша (`x-action-revalidated`) и для истории браузера (`x-action-redirect`), сопровождая их тяжелыми данными самого интерфейса в теле ответа.
* **Реакция клиента (Шаги 7–9):** Получив ответ, браузер мгновенно выполняет инструкции из заголовков. Маркер `'refetch'` запрещает роутеру использовать старую копию страницы из оперативной памяти, а алгоритм сравнения React (Reconciliation) аккуратно «вживляет» пришедшую строку таблицы в текущий DOM-код страницы без перезагрузки экрана.

## 3. Расшифровка системных заголовков Next.js

| Заголовок | Значение / Назначение |
| :--- | :--- |
| **`x-action-redirect: /dashboard/invoices;push`** | Указывает целевой адрес маршрута и метод изменения истории браузера (флаг `;push` вызывает метод `history.pushState`, сохраняя историю переходов для кнопки «Назад»). |
| **`x-action-revalidated: [[],1,0]`** | Инструкция для клиентского **Router Cache**. Массив содержит: <br>1. `[]` — список инвалидированных тегов;<br>2. `1` — флаг инвалидации путей (активирует маркер `'refetch'`);<br>3. `0` — флаг мягкой (точечной) очистки без сброса кэша независимых страниц. |
